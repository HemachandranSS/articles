Zero Trust Module for IoT

It’s critical to build Zero Trust into IoT networks and replace outdated trust models. ns-3 simulations help safeguard vulnerable smart devices.

By Arun Santhosh R.A. and Dr T. Subbulakshmi

Open Source For You  |  November 2026  |  Pages 56–59

Traditional network security functioned like a fortress with a castle-and-moat perimeter. Once a device crossed the perimeter firewall or connected through a gateway, it enjoyed implicit trust across the internal network. This conventional security model falls flat in modern Internet of Things (IoT) deployments. Smart sensors, actuators, and connected appliances are routinely placed in physically accessible spots, run on minimal computing hardware, and transmit data across shared, open networks.

To overcome these vulnerabilities, the Zero Trust architecture establishes a straightforward rule: never trust, always verify. Under the NIST SP 800-207 guidelines, network location alone never grants privilege. Every access request, even from an internal sensor, is treated as if it originates from an untrusted or even compromised network.

The key tenets defined in NIST SP 800-207 applicable to IoT are:

  • Resource protection: All data sources, sensor feeds, and computing services are treated as resources [NIST SP 800-207, Section 2.1, Tenet 1].
  • Per-session trust evaluation: Trust is never permanent; access to individual resources is evaluated on a per-session and per-request basis with least-privilege permissions [NIST SP 800-207, Section 2.1, Tenet 3].
  • Dynamic policy decisions: Access is determined dynamically using identity, device status, and environmental conditions via a Policy Decision Point (PDP) and enforced at a Policy Enforcement Point (PEP) [NIST SP 800-207, Section 2.1, Tenet 4; Section 3].
  • End-to-end encryption and authentication: All communications are secured, authenticated, and encrypted regardless of physical topology [NIST SP 800-207, Section 2.1, Tenet 2].

To facilitate reproducible Zero Trust experiments, the authors have developed and published the Zero Trust IoT library for ns-3 (zero-trust-iot), which is officially available on the NS-3 App Store. The library provides plug-and-play C++ components for cryptographic authentication, runtime context drift re-scoring, and in-line packet filtering. It allows network developers and academic researchers to simulate and benchmark real-world Zero Trust defences without investing in expensive physical sensor testbeds.

Usage of ns-3 in IoT applications

Network Simulator 3 (ns-3) is a widely adopted, discrete-event network simulation engine used extensively by researchers, academics, and industry engineers. In IoT research, procuring and deploying hundreds of physical microcontroller boards, gateways, and radio transceivers is costly and logistically cumbersome.

ns-3 solves this by providing:

  • Realistic simulation of network protocol stacks (IPv4, IPv6, UDP, TCP, point-to-point, 802.11, etc).
  • Deterministic, repeatable experimentation to test network traffic, packet latency, routing behaviours, and protocol interactions under reproducible conditions.
  • A flexible testbed for evaluating security mechanisms and simulating attacks (such as IP spoofing, unauthorised access, and man-in-the-middle exploits) in controlled environments without taking real operational infrastructure at risk.

The Zero Trust module for IoT (zero-trust-iot) extends ns-3 to enable researchers to model and observe how Zero Trust verification mechanisms function over standard network topologies.

Setup needed to simulate a Zero Trust module for IoT

To simulate Zero Trust IoT architectures, the module integrates directly with the ns-3 mainline source tree and relies on the Crypto++ (cryptopp) cryptographic library for cryptographic primitives (such as RSA certificate validation and AES encryption).

  • Simulator: ns-3 (Tested and verified with releases ns-3.45, ns-3.46, and ns-3.47)
  • Crypto library: Crypto++ (cryptopp)
  • Build system: CMake and ns3 wrapper (./ns3)

Modules of the library

The library comprises ten coordinated C++ modules that work together to establish an enforceable trust boundary across every simulated IoT transaction as shown in Figure 1.

  • Identity registry (IdentityRegistry): This acts as a process-wide singleton that registers each ns3::Node alongside its assigned role string and a SHA-256 identity hash derived through ComputeSha256, enabling subsequent authorisation queries via GetRole and GetIdentityHash.
  • Hash utilities (ComputeSha256): Provides a standalone cryptographic utility wrapping Crypto++ SHA-256 to compute lowercase hexadecimal digests used for identity hashing, policy rule fingerprinting, and rule integrity protection.
  • Certificate authority and certificate-based policy (CertificateAuthority, ZtPolicyEngineWithCert): This module simulates lightweight public key infrastructure by generating 1024-bit RSA key pairs, issuing signed identity certificates with node identifier, role, and expiration timestamps via SignIdentity, and validating those credentials using RSA-PSS and an explicit revocation list.
  • Policy engine (ZtPolicyEngine): Serves as the central policy decision point (PDP) defined in NIST SP 800-207. It evaluates access through identity authorization (Authorize), certificate checking (AuthorizeWithCert), revocation enforcement, and role-based micro-segmentation (EvaluateMicroSegmentation). Decisions strictly default to DENY under the least privilege tenet. The engine tracks rule revisions via GetPolicyVersion and exposes a SHA-256 tamper-detection digest through GetPolicyIntegrityHash.
  • Context drift validator (ContextAttributeStore, PeriodicRevalidator): Enforces continuous re-authorization by tracking contextual metrics: time of day, network congestion, and proximity, captured at onboarding. The PeriodicRevalidator regularly computes weighted drift and reduces node trust using exponential decay: Trust = Trust × e^(-λ × drift), calling ZtPolicyEngine::Revoke whenever trust drops below a designated threshold.
  • Dynamic trust scorer (ZtDynamicTrustScorer): Provides session-level anomaly detection between communication pairs. By tracking packet arrival rates across a sliding window through OnPacketReceived, it flags violations exceeding 1.5 times the baseline, penalises consecutive bursts exponentially, permits gradual recovery for compliant traffic, and blocks sessions once trust falls below 25.
  • Encryption utilities (EncryptPayload, DecryptPayload, HexDecodeKey, HexToBytes): Wraps Crypto++ AES-CBC mode to encrypt data payloads with a randomly generated 16-byte initialisation vector prepended to the ciphertext, ensuring transport confidentiality.
  • TLS handshake (ZtTlsHandshake): Coordinates a policy-gated mutual handshake between client and server nodes. Before generating symmetric session keys, it invokes an injected policy validation callback backed by ZtPolicyEngine::Authorize; once cleared, it generates and stores a shared AES key accessible via GetSessionKey.
  • IPv4 enforcement hook (ZtIpv4Hook): Connects directly to an ns3::Node IPv4 stack to intercept outgoing transmission traces (Tx), translating abstract micro-segmentation decisions into real-time network-layer packet forwarding or dropping like an active policy enforcement point (PEP).
  • Logger (ZtLogger): Offers a unified static logging interface featuring optional timestamping, standardising console diagnostics across certificate issuance, validation failures, revocations, and payload cryptographic operations.

Release history and open source contributions

The zero-trust-iot library has evolved across three key public releases on the NS-3 App Store. Version 1.0.0 established the foundational Zero Trust framework compatible with ns-3.45 using Crypto++ primitives. The latest Version 2.0.0 for ns-3.47 expands the suite with five advanced modules covering certificate authorities, dynamic trust scoring, and context drift validation. Distributed under the open source GPLv2 license, the maintainers actively invite community contributions, feedback, and new IoT attack-defence simulation models through its official GitHub repository and issue tracker.

Implementing Zero Trust in IoT networks replaces outdated implicit trust models with strict, continuous verification and least privilege access. Through ns-3 simulations, developers and researchers can easily evaluate how cryptographic handshakes, fine-grained micro-segmentation policies and runtime context monitoring safeguard vulnerable smart devices.

The ten integrated modules of the Zero Trust IoT library successfully counter critical threats including man-in-the-middle attacks, identity spoofing, and unauthorised access. By combining static policy checks with dynamic trust scoring and automated revocation, the library delivers a practical, standard-aligned security framework for next-generation Internet of Things deployments.
