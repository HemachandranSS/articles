Creating Cutting-Edge IoT Devices with the ESP32 C3 Super Mini Board

The ESP32 C3 Super Mini board is a smaller but powerful alternative to the Raspberry Pi Pico boards. The MicroPython code presented in this hands-on guide on the ESP32 C3 board (and its interfacing with real world sensors) also works on the Pi Pico board. Everything has been tested on an Ubuntu LTS laptop with a Docker engine installed on it.

By Ankur Kumar

Open Source For You  |  November 2026  |  Pages 73–79

The ESP32 C3 Super Mini board is a highly economical thumb-sized (less than half in size when compared with any Pi Pico board) IoT powerhouse. It is driven by a 32-bit RISC-V single-core processor, running up to 160MHz with 4MB onboard Flash memory and 400KB SRAM. It comes with 2.4GHz Wi-Fi (802.11 b/g/n, up to 150 Mbps) and Bluetooth 5.0 LE (including Bluetooth mesh) capabilities. The development board is powered by 5V via USB Type-C or 3.3V–6V external input. The price of the Super Mini board with these impressive specs is half that of a Pi Pico board. You could purchase it online through various sites for around Rs 250 to Rs 270 with or without headers soldered.

Figure 1 shows what the board looks like. The power on red LED (left up), onboard blue LED (right down) and reset button (right up) are clearly marked. It is a 16-pin board (8 on each side) with 11 accessible GPIOs providing two 12-bit SAR ADCs up to six channels, six PWM channels, three SPI interfaces, an I2C interface, an I2S interface, two UART interfaces, etc. You can drive both 5V as well as 3.3V devices like sensors through the board. The pin diagram of the board is shown in Figure 2, which you should keep handy to follow for wiring various sensors and the MicroPython code shown in this article.

The board is fully covered by the MicroPython firmware and is totally driven by Thonny IDE and the command line pyboard and mpremote tools introduced in my past articles in OSFY.

Ok, time to lay our hands on the Super Mini board to see it in real world physical action. First, we need to flash the board with an appropriate version of the MicroPython firmware. This could be done through the Thonny IDE or a command line tool called esptool. We’ll use the esptool as that’s more suitable for non-interactive automation pipelines. You can try flashing the board using the Thonny IDE on your own. Just plug the board with USB C data cable into your machine, select the ESP32 board detected in the right bottom corner of the IDE, click on Configure interpreter, select appropriate dropdown entries in the launched Thonny options dialog box Interpreter tab, click on the Install or update MicroPython (esptool) hyperlink, select appropriate dropdown entries in the launched Install MicroPython (esptool) dialog box, click on the Install button and you’re done. Both the dialog boxes with dropdown entries are shown in Figure 3 to kill any confusions. Please note that your device port may not be ACM0 in case multiple IoT boards are plugged into your machine. Just adjust for the correct port value in that case.

Let’s first prepare a Docker image to run the esptool to flash the required MicroPython firmware through the commandline. Create the Dockerfile_Esptool shown below and execute the command docker build . -f Dockerfile_Esptool -t esptool to create esptool Docker image.

Listing 1: Dockerfile_Esptool

#--- Start of Dockerfile_Esptool ---

FROM python:3.14-alpine

SHELL ["/bin/ash", "-o", "pipefail", "-c"]
WORKDIR /tmp
RUN apk add --no-cache curl \
    && pip install esptool \
    && mkdir /etc/esp32c3sm

WORKDIR /etc/esp32c3sm
ENTRYPOINT ["esptool"]
CMD ["-h"]

#--- End of Dockerfile_Esptool ---

Now download the latest version of the MicroPython firmware on your machine by executing the command:

wget "https://micropython.org/$(curl -s https://micropython.org/download/LOLIN_C3_MINI/|grep '\.bin'|grep -v preview|grep href|head -1|awk -F '"' '{print $2}')" -o log -O /tmp/ESP32_GENERIC_C3_Latest.bin

You can also get into a running esptool container to download the MicroPython firmware in case you don’t have write access in your lab machine or want to flash your board in a one-off manner. Just run the command docker run -it --rm --device=/dev/ttyACM0:/dev/ttyACM0 --entrypoint=ash esptool and download the firmware in the container itself through the above shown wget+curl command. Now use esptool erase-flash && esptool write-flash 0 /tmp/ESP32_GENERIC_C3_Latest.bin to finish flashing your board.

Otherwise, execute the following command:

docker run --rm -v /tmp/ESP32_GENERIC_C3_Latest.bin:/tmp/ESP32_GENERIC_C3_Latest.bin --device=/dev/ttyACM0:/dev/ttyACM0 esptool

…to dump a help screen of the tool. Feel free to play with different esptool options and commands shown in the Help screen. Finally, execute these commands to flash the board:

docker run --rm -v /tmp/ESP32_GENERIC_C3_Latest.bin:/tmp/ESP32_GENERIC_C3_Latest.bin --device=/dev/ttyACM0:/dev/ttyACM0 esptool erase-flash

docker run --rm -v /tmp/ESP32_GENERIC_C3_Latest.bin:/tmp/ESP32_GENERIC_C3_Latest.bin --device=/dev/ttyACM0:/dev/ttyACM0 esptool write-flash 0 /tmp/ESP32_GENERIC_C3_Latest.bin

Congratulations! Now your Super Mini board is fully ready to serve you. Please note, the esptool erase-flash command is very handy to start with a clean slate in case your board breaks down later, especially after a firmware upgrade. Now your board has the MicroPython, so the pyboard and mpremote tools covered in the last article (OSFY, September 2026) are fully applicable to it.

Great! It’s time to run some MicroPython code quickly, showing an onboard LED and inbuilt temperature sensor in action. Execute the command:

docker run --device=/dev/ttyACM0:/dev/ttyACM0 pyboard -c 'from machine import Pin;from time import sleep;p=Pin(8, Pin.OUT, value=1);p.toggle();sleep(3);p.toggle()'

…to flash the onboard blue LED. If you have noticed, the onboard LED is active low logic based, which means it is ‘on’ when Pin OUT is low and vice versa. This is opposite to the Pi Pico onboard LED logic.

Next, prepare the MicroPython code shown below, which executes on both the Super Mini board as well as the Pi Pico boards.

Listing: bleditemps.py

#--- Start of bleditemps.py ---
from machine import Pin, soft_reset, Signal, ADC
from os import uname
from time import sleep

pfrn = uname()[-1].split()[-1].replace('-','')
if -1 == pfrn.find('ESP32C3'):
    ahgh = True
else:
    import esp32
    ahgh = False

pled = "LED"
if -1 != pfrn.find('ESP32C3'):
    # onboard LED is invert logic based on ESP32C3 Super Mini
    pled = 8

iled = Signal(Pin(pled, Pin.OUT), invert=not(ahgh))

if -1 == pfrn.find('ESP32C3'):
    isnsr = ADC(4)
else:
    isnsr = None

tglf = True
while True:
    try:
        if tglf:
            iled.on()
        else:
            iled.off()

        if isnsr:
            conversion_factor = 3.3 / 65535
            reading = isnsr.read_u16() * conversion_factor
            # The temperature sensor measures the Vbe voltage of a biased bipolar diode, connected to the fifth ADC channel
            # Typically, Vbe = 0.706V at 27 degrees C, with a slope of -1.721mV (0.001721) per degree.
            itemp = 27 - (reading - 0.706)/0.001721
        else:
            itemp = esp32.mcu_temperature()
        print(" itemp : %.2f C" %itemp)

        sleep(1)
        tglf = not(tglf)
    except:
        iled.off()
        # due to reset the ESP32C3 board got stuck in running
        # after copying main.py to it.
        if -1 == pfrn.find('ESP32C3'):
            soft_reset()

#--- End of bleditemps.py ---

Now execute the command:

docker run --rm -v ${PWD}/bleditemps.py:/etc/rpipico/bleditemps.py:ro --device=/dev/ttyACM0:/dev/ttyACM0 pyboard bleditemps.py

…to run the code on the Super Mini, flashing the onboard LED along with dumping the on-chip temperature sensor readings. Just press the Reset button on the board to end the current run and prepare it to run the next test code snippets. Like the Pi Pico boards, if you copy your code to a main.py file on the board then the Super Mini starts executing this code with every power on. Please note, our code uses a Signal class; this is to abstract Pin objects to take care of active high/low logic to keep the same on/off sequence across different devices. You’ll see us making use of Signal almost everywhere going forward. All this should be enough to warm you up and feel confident to interface with the various useful sensors covered in the next section.

External sensors interfacing with Super Mini

Now let’s interact with the physical world using our amazing Super Mini. First, let’s have some fun with colourful LEDs creating interesting forward/backward/random movements. The code given below arranges red, yellow, green, blue, and white LEDs in a line. These light up in forward and backward motion and finally settle at a random LED light to represent the numbers 1 to 5. When more than one LED lights up it represents the number 6. In a nutshell, we are building an electronic dice game. Isn’t that interesting and exciting?

Listing: chaseleds.py

#--- Start of chaseleds.py ---
from machine import Pin, soft_reset, Signal
from os import uname
from random import randint
from time import sleep

pfrm = uname()[-1].split()[-1].replace('-', '')
ahgh = True
tdly = 0.1

eleds = (
    Signal(Pin(0, Pin.OUT), invert=not(ahgh)),
    Signal(Pin(1, Pin.OUT), invert=not(ahgh)),
    Signal(Pin(2, Pin.OUT), invert=not(ahgh)),
    Signal(Pin(3, Pin.OUT), invert=not(ahgh)),
    Signal(Pin(4, Pin.OUT), invert=not(ahgh)),
)

def aledoff():
    eleds[0].off()
    eleds[1].off()
    eleds[2].off()
    eleds[3].off()
    eleds[4].off()

def aledon():
    eleds[0].on()
    eleds[1].on()
    eleds[2].on()
    eleds[3].on()
    eleds[4].on()

def rledon():
    eleds[0].on()
    eleds[1].off()
    eleds[2].off()
    eleds[3].off()
    eleds[4].off()

def yledon():
    eleds[0].off()
    eleds[1].on()
    eleds[2].off()
    eleds[3].off()
    eleds[4].off()

def gledon():
    eleds[0].off()
    eleds[1].off()
    eleds[2].on()
    eleds[3].off()
    eleds[4].off()

def bledon():
    eleds[0].off()
    eleds[1].off()
    eleds[2].off()
    eleds[3].on()
    eleds[4].off()

def wledon():
    eleds[0].off()
    eleds[1].off()
    eleds[2].off()
    eleds[3].off()
    eleds[4].on()

aledoff()

def chsrlinf(onet = False):
    i = 0
    try:
        while True:
            if i > 4:
                if onet:
                    aledoff()
                    break
                else:
                    i = 0

            if i == 0:
                rledon()
            elif i == 1:
                yledon()
            elif i == 2:
                gledon()
            elif i == 3:
                bledon()
            elif i == 4:
                wledon()

            i += 1
            sleep(tdly)
    except:
        aledoff()
        if -1 == pfrm.find('ESP32C3'):
            soft_reset()

def chsrlinb(onet = False):
    i = 0
    try:
        while True:
            if i > 4:
                if onet:
                    aledoff()
                    break
                else:
                    i = 0

            if i == 0:
                wledon()
            elif i == 1:
                bledon()
            elif i == 2:
                gledon()
            elif i == 3:
                yledon()
            elif i == 4:
                rledon()

            i += 1
            sleep(tdly)
    except:
        aledoff()
        if -1 == pfrm.find('ESP32C3'):
            soft_reset()

def chsrlinfb():
    try:
        while True:
            chsrlinf(True)
            sleep(tdly)
            chsrlinb(True)
    except:
        aledoff()
        if -1 == pfrm.find('ESP32C3'):
            soft_reset()

def chsrand():
    try:
        while True:
            i = randint(0, 4)

            if i == 0:
                rledon()
            elif i == 1:
                yledon()
            elif i == 2:
                gledon()
            elif i == 3:
                bledon()
            elif i == 4:
                wledon()

            sleep(tdly)
    except:
        aledoff()
        if -1 == pfrm.find('ESP32C3'):
            soft_reset()

def randice(onet = False):
    try:
        while True:
            i = 0
            while i < 2:
                chsrlinf(True)
                sleep(tdly)
                chsrlinb(True)
                i += 1

            i = randint(1,6)
            sleep(2 * tdly)

            if i == 1:
                rledon()
            elif i == 2:
                yledon()
            elif i == 3:
                gledon()
            elif i == 4:
                bledon()
            elif i == 5:
                wledon()
            elif i == 6:
                aledon()

            sleep(50 * tdly)

            if onet:
                aledoff()
                break
    except:
        aledoff()
        if -1 == pfrm.find('ESP32C3'):
            soft_reset()

randice()

#--- End of chaseleds.py ---

You can assemble the entire circuit on a mini breadboard. The code indicates that we must connect the positive pins of the red, yellow, green, blue, and white LEDs to the Super Mini GPIO pins 0, 1, 2, 3, 4, respectively. The negative pins of the LEDs are connected to the GND pin of the board (with or without a 220 ohms current limiting resistor). I have soldered the bigger 10mm LEDs on a PCB strip to make it a permanent arrangement ready to serve as a traffic light module as well when using only the first three LEDs. Now let’s use some new sensors, not covered in the earlier article in September, for home automation. The code given below shows how to use a mini IR pyroelectric infrared PIR motion human sensor to create something like a motion-enabled IoT switch. This is a simple circuit to assemble. The VIN/+ve of the sensor is connected to the 3V3 pin of the board, while GND/-ve of the sensor is connected to the GND of the board and the OUT to GPIO 4. Please note, we have intentionally used MicroPython IRQ functionality to demonstrate its usage. MicroPython Interrupt Requests (IRQ) allow your microcontroller to instantly pause its main code and execute a specific function when a hardware event (like a button press or sensor trigger) occurs. This removes the need for wasteful polling in a constant loop. The red, green, blue LED +ve pins are connected to GPIO 0, 1, 3, respectively of the Super Mini. The assembled breadboard circuit is shown in Figure 5. I used an RGB chip LED instead of separate red, green, blue LEDs to keep it small and smart for future needs. Just make a motion around the sensor after running the code and you’ll see the chip LED turning to Red for some time, briefly turning to Blue for a moment, to turn Green again until the next motion is detected. You could also connect relay(s) to the LED(s) pin(s) introduced in the last article in September, to turn on and off electrical devices based upon the nearby motion. You could also throw in some networking code, introduced in the last article, to create highly portable motion-based online IoT devices. Isn’t this another strong reason to make the Super Mini a must-have part of your IoT toolkit?

Listing: pirmtnsnsr.py

#--- Start of pirmtnsnsr.py ---

from machine import Pin, soft_reset, Signal
from os import uname
from time import sleep

pfrm = uname()[-1].split()[-1].replace('-', '')
ahgh = True

if -1 == pfrm.find('ESP32C3'):
    pirs = Pin(4, Pin.IN, Pin.PULL_DOWN)
else:
    pirs = Pin(4, Pin.IN, Pin.PULL_UP)

rgbl = {
        'red' : Signal(Pin(0, Pin.OUT), invert=not(ahgh)),
        'grn' : Signal(Pin(1, Pin.OUT), invert=not(ahgh)),
        'blu' : Signal(Pin(3, Pin.OUT), invert=not(ahgh)),
        }

def rledon():
    rgbl['red'].on()
    rgbl['grn'].off()
    rgbl['blu'].off()

def gledon():
    rgbl['red'].off()
    rgbl['grn'].on()
    rgbl['blu'].off()

def bledon():
    rgbl['red'].off()
    rgbl['grn'].off()
    rgbl['blu'].on()

def aledoff():
    rgbl['red'].off()
    rgbl['grn'].off()
    rgbl['blu'].off()

dly = 5
pln = 0.5

def mtnhdlr(pin):
    if pin.value():
        rledon()
        sleep(dly)
        bledon()
        sleep(1)

pirs.irq(trigger=Pin.IRQ_RISING, handler=mtnhdlr)

aledoff()

while True:
    try:
        if not pirs.value():
            gledon()

        sleep(pln)
    except:
        aledoff()
        if -1 == pfrm.find('ESP32C3'):
            soft_reset()

#--- End of pirmtnsnsr.py ---

Our next sensor module to play with is an IR infrared obstacle avoidance sensor module. It has a pair of infrared transmitting and receiving sensors. When the transmitted light waves are reflected back, they will be received by the receiver. The onboard comparator circuitry does the processing and the green indicator LED comes to life. The simple code shown below is all that you require to start with the module. Please note the usage of Signal class to abstract the active low logic-based output from the sensor module.

Listing: obstklesnsr.py

#--- Start of obstklesnsr.py ---
from machine import Pin, soft_reset, Signal
from os import uname
from time import sleep

pfrm = uname()[-1].split()[-1]
ahgh = True

eleds = (
    Signal(Pin(0, Pin.OUT), invert=not(ahgh)),
    Signal(Pin(1, Pin.OUT), invert=not(ahgh)),
    Signal(Pin(2, Pin.OUT), invert=not(ahgh)),
)

esnsr = Signal(Pin(5, Pin.IN), invert=ahgh)

def aledoff():
    eleds[0].off()
    eleds[1].off()
    eleds[2].off()

def rledon():
    eleds[0].on()
    eleds[1].off()
    eleds[2].off()

def gledon():
    eleds[0].off()
    eleds[1].on()
    eleds[2].off()

def bledon():
    eleds[0].off()
    eleds[1].off()
    eleds[2].on()

aledoff()

try:
    while True:
        if esnsr.value():
            rledon()
            sleep(5)
        else:
            gledon()
            sleep(0.5)
except:
    aledoff()
    if -1 == pfrm.find('ESP32C3'):
        soft_reset()

Last but not the least, there are a useful set of gas sensor modules like MQ-2 and MQ-135 to interface with the Super Mini. The MQ-2 gas sensor allows you to monitor LPG, smoke, and flammable gases. The MQ-135 is a popular metal oxide semiconductor gas sensor module. It detects and measures airborne contaminants like ammonia, nitrogen oxides (NOx), benzene, smoke, alcohol, and carbon dioxide. You could easily build a portable air quality device using these and the DHT temperature humidity sensor used in the last article. Just note, you have to connect MQ sensors VCC to the Super Mini 5V pin as those sensors use a small heater inside. You must also let the MQ sensors power up for a day to get them ready to provide correct output. You can add an inexpensive, easy-to-use 4-digit, 7-segment LED display module TM1637. Utilising the TM1637 driver IC, it requires only two data/clock pins to interface with the Super Mini, making it perfect for displaying sensors data.

The code given below is for a portable air quality monitoring device based upon DHT11, MQ-2/135 sensor modules, using the TM1637 library inline (link provided in the Reference section).

Listing: tempnumgss.py

#--- Start of tempnumgss.py ---
# include TM1637 library code
# not shown here due to length

import dht
from machine import Pin, ADC, Signal, reset
from os import uname
from time import sleep

pfrm = uname()[-1].split()[-1].replace('-', '')
if -1 != pfrm.find('ESP32C3'):
    import esp32
    iahgh = True
else:
    iahgh = False

pild = "LED"
if -1 != pfrm.find('ESP32C3'):
    # onboard LED is invert logic based on ESP32C3 Super Mini
    pild = 8

iled = Signal(Pin(pild, Pin.OUT), invert=iahgh)

ahgh = False
eleds = (
    Signal(Pin(0, Pin.OUT), invert=ahgh),
    Signal(Pin(1, Pin.OUT), invert=ahgh),
    Signal(Pin(3, Pin.OUT), invert=ahgh),
)

if -1 == pfrm.find('ESP32C3'):
    isnsr = ADC(4)
else:
    isnsr = None

esnsr = Pin(5)
esnsr = dht.DHT11(esnsr)

mq2ao = ADC(2)
if -1 != pfrm.find('ESP32C3'):
    mq2ao.atten(ADC.ATTN_11DB)

ss = TM1637(Pin(6), Pin(7))

def aledoff():
    iled.off()
    eleds[0].off()
    eleds[1].off()
    eleds[2].off()

def rledon():
    eleds[0].on()
    eleds[1].off()
    eleds[2].off()

def gledon():
    eleds[0].off()
    eleds[1].on()
    eleds[2].off()

def bledon():
    eleds[0].off()
    eleds[1].off()
    eleds[2].on()

def getietemphdt():
    iled.on()
    sleep(2)
    iled.off()

    if isnsr:
        conversion_factor = 3.3 / 65535
        reading = isnsr.read_u16() * conversion_factor
        # The temperature sensor measures the Vbe voltage of a biased bipolar diode, connected to the fifth ADC channel
        # Typically, Vbe = 0.706V at 27 degrees C, with a slope of -1.721mV (0.001721) per degree.
        itemp = 27 - (reading - 0.706)/0.001721
    else:
        itemp = esp32.mcu_temperature()

    try:
        esnsr.measure()
    except:
        aledoff()

    etemp = esnsr.temperature()
    hum   = esnsr.humidity()
    if -1 != pfrm.find('ESP32C3'):
        gsra = mq2ao.read()
        gsrv = (mq2ao.read_uv())/1000000
    else:
        gsra = mq2ao.read_u16()
        gsrv = gsra * (3.3 / 65535)

    if etemp <= 30.00:
        gledon()
    elif etemp > 30.00 and etemp <= 35.00:
        bledon()
    elif etemp > 35.00:
        rledon()

    print("%.2f, %.2f, %.2f, %d, %.2f" % (itemp, etemp, hum, gsra, gsrv))
    ss.numbers(int(etemp), int(hum))
    sleep(2)
    ss.number(gsra)

while True:
    try:
        getietemphdt()
    except:
        aledoff()
        if -1 == pfrm.find('ESP32C3'):
            reset()

#--- End of tempnumgss.py ---
